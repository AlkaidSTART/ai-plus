# 后端分阶段实施总纲

## 使用方式

- 本目录是后端整体实施规划，不是已完成功能清单。各阶段目录在规划时只存放 `plan.md`；某阶段实施完成后，在该阶段目录追加 `result.md`（文件名统一，不用 `results.md`；未实施的阶段不预建）。序号表达依赖顺序，不包含日期或工期安排。
- 本轮仅授权探索和编写这些计划，不表示已授权执行全部后端开发、付费调用、部署或数据迁移。Agent 接到具体阶段实施指令后再开展该阶段工作。
- 开始某阶段前，重新读取根目录 AGENTS.md、该阶段计划、相关源码和契约，核实前置阶段的验收证据；不得把存在代码或已勾选清单当成验收证据。
- 清单中的新文件是拟新增路径，不是已有实现。新依赖只在对应能力必需且选型已核实后引入；使用实际安装版本的官方文档/源码确认 API，不凭记忆编写接口。
- 发现文档和代码不一致时先列出差异，涉及业务口径、身份方案、外部来源、公共 API 或数据库兼容性时确认后再实施。后续阶段的待决项不是任意发挥的授权。
- 阶段只完成一个明确交付范围，不顺便开展相邻阶段；P1/P2 不阻塞 P0 验收。
- 本次（规划动作）不改写 docs/plans 的历史记录或 AGENTS.md。2026-09-10 修订：原“不生成 result.md”仅指规划动作本身；此后各阶段实施完成后，必须按 AGENTS.md 强约束在对应阶段目录生成 `result.md`。正式实施时的结果记录遵循届时有效指令，本总纲不永久覆盖项目工作协议。

### 本轮实际验证

在 backend 目录运行：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m pytest -q -p no:cacheprovider
```

结果：**2 passed，3 warnings**。警告分别涉及 Starlette/httpx 测试客户端弃用、AnyIO BlockingPortal 别名弃用、未知 `asyncio_mode` 配置。没有据此自动安装新库。

另外使用该解释器运行内联只读探针：

- `len(Base.metadata.tables)` 为 18；所有表的显式业务唯一约束和索引计数均为 0。
- `poll_once()` 返回 False。
- `/health` 返回 200；任务列表返回 501。
- 缺少 Idempotency-Key 返回默认 detail 格式的 422。
- 11 个相同 ASIN 在去重前被 schema 拒绝为 422。
- 反向日期窗通过当前请求校验，进入 501 占位逻辑，而非返回日期错误。
- 按现有 Alembic URL 转换构建引擎，报 `ModuleNotFoundError: No module named 'psycopg2'`，未连接或修改数据库。

**未验证**：真实 PostgreSQL 扩展与迁移、容器启动、外部来源、模型调用、前端联调、性能和生产隔离。未给出无依据的完成百分比。
