# 阶段 02：数据来源与模型验证

## 目标与前置条件

验证首个品类的真实数据来源与文本模型链路，给后续 Agent 明确输入条件和质量验收集，而不是先写供应方占位接口。

依赖 [阶段 01](../01-基础配置与迁移/plan.md) 的可运行环境；来源调查可独立进行。依据 `docs/PRD.md` P0 与 M0-A、`docs/技术方案.md` §1.3、§5.2、§9、§10。真实请求前需确认账号权限、授权来源、费用预算及样本留存许可。

## 当前缺口

仓库没有真实采集适配、真实测试样本、bge-m3/LLM 集成，也没有已确认 child ASIN 集合、充分性门槛、质量阈值和调用预算。示例 ASIN 与 fixtures 说明不能替代验证。

## 文件范围

拟新增：`backend/tests/fixtures/` 下合法、脱敏、明确标注来源性质的评估样本；`backend/tests/test_provider_contract.py`；必要的最小验证脚本放在 `backend/` 内，具体文件名按选定供应方确定。

可改：`backend/pyproject.toml`、`backend/uv.lock`、`backend/README.md`、`docs/技术方案.md` 的已确认选型与验证口径。仅实际集成必需时增加依赖，不搭建多供应方通用插件系统。

## 实施步骤

- [ ] 确认单品类、Amazon US、5–10 个真实 child ASIN、可访问数据来源及来源许可；区分商品存在性、父子变体与编码格式。
- [ ] 阅读候选来源的当前官方接口文档，验证商品元数据、评论原文、来源 ID、时间、星级、语言、分页、图片关联及历史覆盖。不假定 Keepa 或任一供应方能够提供全部原文。
- [ ] 对每个 ASIN 记录实际原始数量、分页限制、星级/语言/月份分布、原始时间精度、缺失原因、费用和限流行为。200–500 条是目标而非保证；禁止补造。
- [ ] 固定成功/失败/合法零样本定义，提出并确认 SUFFICIENT/LIMITED/INSUFFICIENT 门槛、缓存有效期、事件保留策略和单任务成本边界。
- [ ] 建立人工核对样本：短有效缺陷、无意义评论、同评论多问题、跨语言近义、不同部件误合并、无有效差评、伪造引用和评论中的提示注入。
- [ ] 核实实际可调用的文本模型 ID、版本、结构化输出与超时/限流接口。名称必须来自可用性验证，不照抄 PRD 历史 Claude 名称。
- [ ] 验证 bge-m3 Dense 1024 维输出、模型修订号、运行硬件及批量能力；据实决定单进程装载还是独立推理服务，避免两种方案同时实现。
- [ ] 用同一标注集评估片段提取、跨语种聚类、双栏支持关系，给出实际质量和误差例子。确认聚类阈值、单例处理、严重度聚合与抽样验收规则。
- [ ] 核查并确认 P0 空指标口径：潜力指数与 FBA 未评估，不用 0 代替；PRD 与技术草案的冲突须有明确结论后再交给阶段 07。
- [ ] 将供应方字段映射、错误分类、可用模型修订、样本边界及费用依据写入现有技术说明；真实样本与合成夹具明确分开，密钥不入库。

## 验证与验收

- [ ] 每个验证 ASIN 都有可核对来源与覆盖记录；不能访问的 ASIN 如实失败，不把合成数据计入成功率。
- [ ] 实际执行一次文本生成与一次 1024 维向量调用，记录模型标识、耗时、计量与实际账单/估算区别。
- [ ] 外部错误能区分授权失败、限流、超时、无数据；无限重试被禁止。
- [ ] 评估样本可离线重放；引用必须真实存在于原文；无凭证环境默认不执行付费测试。
- [ ] `uv run pytest -q tests/test_provider_contract.py` 验证已确认的字段映射和错误边界；离线测试不能充当真实调用证据。

## 非目标与停止条件

不实现生产采集管道、视觉服务、财务或前端。没有可授权来源/凭证/模型预算时，仅完成调查并明确阻塞；基础任务 API 可继续，但阶段 05/06 的真实闭环不能宣称通过。

## 交接

向阶段 05 提供数据来源和清洗约定；向阶段 06/07 提供模型版本、调用方式、评估集和已批准阈值；未决项必须保持未决，不能由实施 Agent 自行填数。
