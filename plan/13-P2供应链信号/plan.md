# 阶段 13：P2 供应链信号

## 目标与进入门禁

从经授权的外部运价、港口、材料或交期信号生成可追溯风险提示；输入不足时只给有条件建议，不编造精确安全库存。

依赖 [阶段 08](../08-鉴权隔离与P0验收/plan.md)，不默认依赖其他 P2 能力。依据 PRD P2-03、`docs/技术方案.md` §8。当前没有信号来源、影响规则、历史样本或通知接口。

进入前确认一个最小来源与信号类别、采集许可、刷新/失效策略、影响品类/线路映射及评估标准；如要求库存数量，先确认销量、交期、服务水平和计算规则。

## 文件范围

拟新增：`backend/app/services/supply_chain.py`、信号/规则结果增量迁移、确认后的独立查询资源/schema、`backend/tests/test_supply_chain.py`、`test_signal_quality.py`。

可改：`db/models.py`、`app/main.py`、`docs/api.md`；仅确有周期运行需求并获确认时复用 worker 增加信号采集入口，不另建未经需要的调度平台。

## 实施步骤

- [ ] 验证最小来源的数据结构、发布时间、观测时间、地域/线路/品类、单位与访问限制，区分原始事实与舆情文本。
- [ ] 冻结独立信号与风险查询契约，定义唯一来源标识、版本、有效期、过期/不可用状态，不能复用 P0 报告的完成状态表达行情有效性。
- [ ] 采集保留出处、观测时间与原始数值；同来源重复项去重，修正数据创建新版本，不覆盖已出具建议的依据。
- [ ] 使用确认规则把信号映射到企业品类/线路，保存 rule_version、输入值、阈值与解释；模型只辅助文本归纳，不自行决定企业业务动作。
- [ ] 来源不可用、过期、相互冲突或覆盖不足时明确提示，不能把缺数据显示为零风险。
- [ ] 缺销量/交期/服务水平时只给定性条件建议；确需数量时先确认公式、单位、数据窗口及边界，再使用确定性计算器实现。
- [ ] 长周期采集和重试遵守授权、成本、取消及幂等边界，来源异常不拖垮 P0 分析队列。
- [ ] 按租户授权查询企业风险结果，原始公共信号复用与企业私有业务输入分离，日志不得泄漏企业库存明细。

## 验证与验收

```bash
cd backend
uv run pytest -q tests/test_supply_chain.py tests/test_signal_quality.py
uv run pytest -q
```

- [ ] 每条风险结果能追溯到来源、规则、输入及适用范围，历史建议可复算。
- [ ] 重复、修正、过期、缺值、冲突来源、错误单位、采集失败均有样本。
- [ ] 缺业务参数不返回精确库存数；有数量算法时用独立手算样例验证。
- [ ] 跨租户结果不能互读，来源轮询失败不影响既有任务状态和报告。
- [ ] 在已确认样本集评估风险识别，不把新闻数量或模板建议数量当业务准确率。

## 非目标与停止条件

不自动采购、调库存或发送外部短信/邮件/飞书消息；通知渠道若有需求需独立确认。没有信号来源、影响规则或库存输入时不扩大为预测平台，也不虚构风险结论。

## 交接

交付独立风险查询契约与来源/限制说明；后续通知、库存执行和前端页面均是另外的任务，不隐含于本阶段。
