# 阶段 09：P1 视觉取证

## 目标与进入门禁

在已验证文本闭环上增加真实买家图片观察和证据溯源，图像失败时保留文本结果。依赖 [阶段 08](../08-鉴权隔离与P0验收/plan.md)；财务阶段不是本阶段前置条件。

依据 PRD P1-01/P1-03、`docs/技术方案.md` §4–5、`docs/api.md` §8。当前只有占位字符串，图片表、下载服务和 VLM 均未实现。必须先确认图片使用权限、可用 VLM、对象存储、留存策略、质量样本及 P1 phase/API 扩展契约；当前 P0 契约不接受 P1，不得直接透传未经定义的枚举。

## 文件范围

可改：`backend/app/worker/graph.py`、`worker/nodes.py`、`api/routes/reports.py`、`api/schemas.py`、`db/models.py`、`config.py`、必要依赖/锁文件及 `docs/api.md`。

拟新增：`backend/app/services/vision.py`、最小图片下载/存储适配、图片/视觉证据增量迁移、`backend/tests/test_vision.py`、`test_image_security.py`、`test_evidence_filters.py`。存储选型确认前不创建完整图片平台。

## 实施步骤

- [ ] 以真实评论版本关联图片，保存来源 URL、内容 hash、对象标识与观测信息，去重不丢失评论关系；图库图和合成图不能算买家证据。
- [ ] 验证下载来源和每次重定向目标，限制大小、解码尺寸、媒体类型与超时，阻断回环/私网/链路本地等 SSRF 目标；防止解析地址与实际连接地址不一致。
- [ ] 对象存储按租户和证据关系授权访问，凭据仅后端加载；明确删除/留存与报告证据引用关系，不能公开整个存储桶。
- [ ] 先用标注样本验证 VLM 输出，schema 分开保存可见观察、可能成因、待实物验证事项、模型置信度与模型/提示版本。
- [ ] 定义并确认 bbox 坐标系、单位与原图尺寸转换；没有可靠定位时为 null，不制造框选。置信度不能描述成校准准确率。
- [ ] 视觉节点置于聚类后、建议前，并只在明确启用的 P1 流程执行；P0 保持原七节点。图片异常发 warning 并继续文本，不伪造视觉成功。
- [ ] 将视觉证据与建议、评论版本按同报告链路关联，不能仅凭照片断言材质牌号、尺寸、公差或缺陷因果；保留包装损伤这类有效履约证据。
- [ ] 扩展 evidence 的 rating/日期/language 筛选、译文、图片及 code point 高亮；返回 total 和 filtered_total 的区别，分页不改变卡片总体证据数。
- [ ] 扩展 phase、响应字段和事件/节点清单前先冻结契约及兼容方式，确保旧 P0 客户端不会将新节点或空字段误判为完成。

## 验证与验收

```bash
cd backend
uv run pytest -q tests/test_vision.py tests/test_image_security.py tests/test_evidence_filters.py
uv run pytest -q
```

- [ ] 真实获授权样本覆盖有效损伤、包装损伤、无关图片、无 bbox、模型超时，质量门槛先确认再验收。
- [ ] 内网 URL、重定向绕过、超大图片、错误媒体类型及越权对象访问被拒绝。
- [ ] VLM 失败仍可生成带限制说明的文本报告，P0 结果及已发布历史不变化。
- [ ] 过滤后的证据数可核对，多个建议共享图片/评论不会重复抬高计数；emoji 高亮正确。

## 非目标与停止条件

不实现财务、图片编辑器或自动采购，不因 VLM 输出就认定工程事实。没有图片授权、存储方案、坐标契约或质量样本时，停止相关实现并明确未具备 P1 入口条件。

## 交接

提供 P1 视觉/证据扩展契约与真实降级案例。前端画廊、框选与筛选 UI 另行授权；本阶段不顺便重写页面。
