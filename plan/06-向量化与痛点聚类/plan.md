# 阶段 06：向量化与痛点聚类

## 目标与前置条件

从冻结评论生成可追溯片段、bge-m3 向量与最多五个展示痛点，统计全部由真实关联计算。

依赖 [阶段 02](../02-数据来源与模型验证/plan.md) 的模型、标注集和阈值、[阶段 05](../05-采集清洗与数据快照/plan.md) 的快照。依据 `docs/技术方案.md` §4.2–4.3、§5.2 及 `docs/api.md` §5。

## 文件范围

已有：`backend/app/worker/nodes.py`、`worker/graph.py`、`db/models.py`、`pyproject.toml`、`uv.lock`。

拟新增：`backend/app/services/embedding.py`、`clustering.py`、相应增量迁移、`backend/tests/test_fragments.py`、`test_embedding.py`、`test_clustering.py`。先确认模型是否使用外部服务，不默认安装本地 GPU 全家桶。

## 实施步骤

- [ ] 固定 P0 聚类输入为已确认有效低星评论集合；若将好评片段纳入，则先确认独立分母口径，不能混入低星统计。
- [ ] 提取抱怨片段并保存原文位置、片段文本与 extraction_version；以原始文本校验摘录，拒绝模型创造的原声。
- [ ] 统一偏移单位为 Unicode code point，处理 emoji、组合字符、重复短语和长评切分；清洗文本与原文不同则保存可核验映射，不靠猜偏移。
- [ ] 调用阶段 02 选定 bge-m3 推理方式，校验每条 Dense 向量长度 1024、数值有限且可计算余弦相似度；错误/零范数等异常不得替换随机向量。
- [ ] 复用键绑定原文片段哈希、切分版本、模型修订和租户/快照可见范围。不同模型或切分规则不误复用。
- [ ] 将向量持久化并建立精确相似度基线；引入 HNSW 索引时使用已安装 pgvector 版本支持的方式，以实际租户/快照过滤对比召回，HNSW 不承担聚类算法职责。
- [ ] 按已验证阈值和稳定输入顺序分配最近簇中心或建立新簇，保存算法版本、阈值、单例处理及未归类情况；不得临时发明上线阈值。
- [ ] LLM 仅为簇命名、标准维度和严重度理由提供结构化输出；服务端验证类别、1–5 级范围和来源支持关系。
- [ ] 频次按独立 review 去重，不按片段数；分母来自同一快照的有效低星评论。Top 5 按已确认稳定规则排序，少于五类保持实际数量，并保留其他簇和未归类统计。
- [ ] 处理现有 issue_clusters 必须引用 report_id 的建模关系：在首次写簇前，与阶段 07 明确未发布分析产物如何持久化。可采用最小暂存产物或显式未发布版本，方案确认后迁移；不能先伪造 published_at 把半成品当报告。
- [ ] 接入 embedding/clustering 节点及恢复逻辑，提交产物时再次检查租约；失败不得发布任何残缺报告。

## 验证与验收

```bash
cd backend
uv run pytest -q tests/test_fragments.py tests/test_embedding.py tests/test_clustering.py
uv run pytest -q
```

- [ ] 每个 fragment 都能从原文精确定位，异常偏移/虚构摘录被拒绝。
- [ ] 多片段同评论只计一次，同评论可支持多个簇；占比合计可超过 100%，不归一化伪装互斥分布。
- [ ] 空集合、零分母、少于五簇、跨语言同义、不同部件误合并均有固定样本。
- [ ] 精确检索与 HNSW 的带过滤召回和延迟分别记录；未达标不能删除质量门槛。
- [ ] 真模型在标注集达到阶段 02 确认的验收条件；记录错误案例而不是只展示最好样本。
- [ ] 重启与向量缓存失效测试不产生重复成员、错模型复用或跨快照数据污染。
