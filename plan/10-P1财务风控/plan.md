# 阶段 10：P1 财务风控

## 目标与进入门禁

实现绑定已发布报告版本的确定性财务情景，输出可复核现金流、规则命中和独立否决状态，不让 LLM 计算金额。

依赖 [阶段 08](../08-鉴权隔离与P0验收/plan.md)，不强依赖视觉阶段。读取 `docs/技术方案.md` §7、`docs/api.md` §8、PRD P1-02。当前没有财务表、费率表或正式财务接口；前端原型参数不得作为真实规则。

进入前必须确认：老品增量/新品项目口径、ROI 期间与分母、现金流窗口、币种单位、规则阈值、费率来源及有效范围、缺参数行为与身份权限。

## 文件范围

拟新增：`backend/app/services/financial.py`、确认契约后的财务路由、情景/结果增量迁移、`backend/tests/test_financial.py`、`test_financial_api.py`、`test_financial_versions.py`。

可改：`db/models.py`、`api/schemas.py`、`app/main.py`、`docs/api.md`；只在获批替代方案需要时修改 proposal 服务。不重跑采集，不修改原任务终态。

## 实施步骤

- [ ] 先冻结“输入情景 → 计算结果”的独立资源契约，绑定 report_id/report_version，明确币种/单位、必需项、公式/费率/规则版本和授权；路径未确认前不直接落路由。
- [ ] 情景输入保存用户提供、来源实测、情景假设三种依据，版本不可变；用户修改参数产生新情景，不覆盖旧结果。
- [ ] 全程 Decimal 计算，JSON 金额为十进制字符串并带币种；防止 float 漂移、负数/溢出、除零与无穷值。
- [ ] 分开老品增量收益与新品项目收益。MOQ 作为采购/付款约束，不当销量；模具费不得既一次性扣除又重复摊销扣除。
- [ ] 确定性逐期现金流包含采购、模具、物流、运营和回款时滞；回收期来自累计现金流，窗口内未回本明确表示，不用 999 等哨兵数字。
- [ ] 缺必需参数或有效费率时 NOT_EVALUATED 并返回 missing_fields，不将 null 当 0，不默认通过。
- [ ] PASSED/VETOED 由确认规则计算，返回 rule_id、输入、阈值、公式版本及假设。财务否决不把原 COMPLETED 任务改成 FAILED。
- [ ] 核验 Amazon 官方当期费用依据，区分可售包装/外箱、实重/体积重、单位、站点、计费规则与生效范围；不能用海运体积重公式替代 FBA 规则。
- [ ] 可选一次受约束替代建议仅在已确认范围内实现：保留原否决、创建新方案版本、重新验证证据并重新计算；不能让 LLM 改规则以得到通过。
- [ ] 对财务数据实施已确认的存储/备份保护和日志脱敏，限制成员访问，不顺便接支付或采购系统。

## 验证与验收

```bash
cd backend
uv run pytest -q tests/test_financial.py tests/test_financial_api.py tests/test_financial_versions.py
uv run pytest -q
```

- [ ] 使用业务确认的手算样例/独立表格核对金额与现金流，不用同一实现生成自己的期望值。
- [ ] 覆盖零投入、零销量、负贡献、缺费率、跨币种、回款延迟、窗口内不回本、边界阈值、重复成本。
- [ ] 同输入和同规则版本可复算；参数改动产生新版本，旧报告/情景保持不变。
- [ ] 越权读取/写入被拒绝，日志无敏感完整财务输入；VETOED 不影响执行状态语义。

## 非目标与停止条件

不承诺收益、不自动放款/停产/采购，不实现未经定义的潜力指数。不清楚 ROI、规则阈值或费率来源时停在口径确认，不能照抄原型数值上线。

## 交接

输出情景 API、公式与版本依据、边界样例及规则解释供前端对接。视觉可独立交付；若需要整合自动财务节点，须另行确认与独立情景 API 的一致性，避免双套算法。
