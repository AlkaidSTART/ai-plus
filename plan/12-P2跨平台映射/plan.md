# 阶段 12：P2 跨平台映射

## 目标与进入门禁

对有授权数据的 Amazon/TikTok Shop/Temu 商品生成可解释同款候选及可核对价格比较，匹配候选不等于确认同款。

依赖 [阶段 08](../08-鉴权隔离与P0验收/plan.md)，不依赖回测；若选定方法必须使用视觉能力，再明确增加阶段 09 前置条件。依据 PRD P2-02、`docs/技术方案.md` §8、`docs/api.md` §8。

当前没有跨平台来源、匹配标注集或独立接口。必须先确认平台来源权限、商品字段、币种税费口径、同款标签和误匹配验收标准。

## 文件范围

拟新增：`backend/app/services/product_matching.py`、已验证平台的最小采集适配、匹配关系/比较快照增量迁移、确认后的匹配资源路由/schema、`backend/tests/test_product_matching.py`、`test_price_comparison.py`。

可改：`db/models.py`、`app/main.py`、`docs/api.md`。不直接解除 P0 创建任务的 amazon/US 限制，也不把 TikTok/Temu 商品 ID 填入 ASIN 字段。

## 实施步骤

- [ ] 按平台验证实际可得字段、分页、图片/文本来源与费用，保存平台独立商品 ID 和观测时间，不假设字段与 Amazon 完全一致。
- [ ] 确认产品模型的最小扩展策略及独立资源契约，保留平台/站点/规格差异；已有 P0 ASIN 和唯一约束保持兼容。
- [ ] 收集人工标注的同款/近似款/不同款商品对，含多件套、尺寸、材料、规格与变体差异，明确错误匹配成本和验收标准。
- [ ] 使用已验证文本/图像特征和规格约束生成候选，保存匹配算法/模型版本、得分及支持与冲突理由；不把相似度当校准概率。
- [ ] 确认后的同款关系与算法候选分离，保存确认/拒绝的依据与审计记录；新模型重算不能覆盖人工确认或改写旧比较结果。
- [ ] 价格比较统一币种、汇率来源及生效信息、件数/单位、税费、佣金、履约范围和观测时点；缺成本项明确标记不可完整比较。
- [ ] 保存不可变比较快照和来源，让每项差价可复核。毛差价不等于净利润，不用缺成本数据生成套利保证。
- [ ] 新查询/操作复用会话、租户、分页及错误信封，跨租户候选与确认关系不得互见。

## 验证与验收

```bash
cd backend
uv run pytest -q tests/test_product_matching.py tests/test_price_comparison.py
uv run pytest -q
```

- [ ] 标注集测误匹配/漏匹配，按预先确认门槛验收，不只列高分示例。
- [ ] 缺规格、多件套、图片近似但不同商品、人工拒绝后重算均正确处理。
- [ ] 单位、汇率、税费缺失和观测时点不一致不会生成假精确净收益。
- [ ] P0 仍拒绝非 amazon/US 输入；独立匹配接口不影响原任务幂等与证据链。

## 非目标与停止条件

不做自动调价、跨平台下单或账号批量管理；不在来源与标签缺失时创建“已匹配”演示数据。公共商品模型兼容性未确认时先停在设计门禁。

## 交接

提供候选/人工确认状态语义、比较来源和限制，前端三平台比较 UI 独立实施；映射结论不回写旧 ASIN 报告。
