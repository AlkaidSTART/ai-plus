# 阶段 11：P2 历史回测

## 目标与进入门禁

为已冻结分析结果建立独立历史评估流程，区分真实 as-of 回测与事后回顾，禁止向 P0 task 添加演示常量准确率。

依赖 [阶段 08](../08-鉴权隔离与P0验收/plan.md)。读取 PRD P2-01、`docs/技术方案.md` §8、`docs/api.md` §8。当前仅 evolution 占位，没有历史评估表、接口或 as-of 样本；不依赖视觉/财务阶段，除非获批评估目标确实使用对应产物。

进入前确认：历史数据来源及可用性、评估对象/目标、截点、后验窗口、指标、基线、样本数与通过标准。未知时先验证可行性，不默认具备历史数据。

## 文件范围

拟新增：`backend/app/services/backtesting.py`、确认后的独立评估路由/schema、评估记录与冻结输入的增量迁移、`backend/tests/test_backtesting.py`、`test_temporal_isolation.py`。

可改：`db/models.py`、`app/main.py`、`docs/api.md`。按需复用现有受限任务执行机制，不改变 P0 任务结果或把回测强加为第八个节点。

## 实施步骤

- [ ] 盘点历史快照，验证来源实际观测时间和评论原始时间，判断是否真的能够还原截点时可用输入。
- [ ] 输入同时限定 reviewed_at <= cutoff 与 observed_at <= cutoff；后验数据独立读取。今天采到的旧评论只能做回顾性分析，标签与接口需明确区别。
- [ ] 与业务冻结评估指标、计算期、对照基线、样本集合及排除规则；不定义一个含糊 backtest_accuracy 字段来容纳所有结果。
- [ ] 冻结输入 snapshot、模型修订、提示词、pipeline 版本、建议与截点，保存不可变评估身份及 lineage。
- [ ] 定义并确认独立评估资源和结果 schema，复用 tenant/report 授权；长任务复用有界执行/取消/恢复机制，不在请求内阻塞跑全部模型。
- [ ] 严格隔离输入与后验指标数据，查询层显式校验时间范围，禁止把后验文本拼进分析提示。
- [ ] 报告输出实际样本数、排除原因、指标值、基线差异及不确定性；数据不足输出不可评估，不虚构准确率。
- [ ] 披露模型知识可能包含截点后信息，检索时间过滤不能保证模型知识无泄漏；不把后续销量相关性写成改款因果证明。

## 验证与验收

```bash
cd backend
uv run pytest -q tests/test_backtesting.py tests/test_temporal_isolation.py
uv run pytest -q
```

- [ ] 截点前后、评论日期早但观测日期晚、缺观测时间、无后验数据均有边界测试。
- [ ] 人为插入后验信号不能进入输入集合；跨租户快照/报告引用被拒绝。
- [ ] 同一冻结输入和指标版本可复算；模型外部非确定性与结果复算范围分开说明。
- [ ] 独立手算/标注集验证评估指标，报告能清楚区分 as-of 回测与回顾性分析。

## 非目标与停止条件

无历史可用数据不得宣称已完成真正回测；不抓取无授权数据，不保证策略收益，不扩张到交易自动执行。指标和数据入口未确认时不提前固化数据库 schema。

## 交接

交付独立评估 API、时间隔离证据和指标定义，前端展示另行授权；不会改变既有 P0/P1 报告的内容或状态。
