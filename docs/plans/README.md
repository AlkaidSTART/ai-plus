# 任务计划与结果记录

强约束见 [AGENTS.md](../../AGENTS.md) 的“任务计划与结果记录”一节。

## 目录约定

每次实施任务一个目录：`YYYY-MM-DD-<任务简称>/`。同一任务的修订沿用原目录；同日同名的独立任务加序号，不能覆盖历史任务。

```text
docs/plans/
├── README.md
└── YYYY-MM-DD-<任务简称>/
    ├── plan.md     # 实施前生成，提交审核
    └── result.md   # 实施结束后生成；审核前不创建
```

## 强制流程

1. **探索与计划**：先只读探索，再创建任务目录与 `plan.md`，写清目标、依据、文件范围、步骤、验证及风险，标记“待审核”。
2. **提交审核并停止**：向用户提供计划路径和摘要，等待计划展示后的明确批准。初始任务请求不代表批准尚未展示的计划，不得补造审批。
3. **审核前边界**：仅允许只读探索和当前任务目录、`plan.md` 的创建或修订。这是全局“审核前不得修改文件”约束的项目级例外，其他实施操作仍被禁止。
4. **按计划实施**：获批后在 `plan.md` 记录真实审批信息，只实施批准范围。范围或验收标准等实质变化须先修订计划、说明原因并重新审核。
5. **验证并输出结果**：实施结束后生成同目录的 `result.md`，记录实际变更、验证、偏差与遗留事项，并向用户提供结果路径和摘要。不得把实施结果混写回 `plan.md` 或提前生成成功结果。
6. **如实记录失败**：阻塞、失败或中止同样输出 `result.md`，明确原因与剩余工作，不得标记完成；未运行的检查不能写成通过。

## plan.md 最小模板

```markdown
# <任务名>

## 审核状态
待审核。批准后记录用户的真实批准信息；实质性修订后重新等待审核。

## 目标
可观察的交付目标。

## 当前事实
代码、文档或命令依据。

## 变更范围
预计变更的具体文件。

## 实施步骤
1. ……

## 验证与验收
具体检查命令与验收条件。

## 风险与非目标
不确定事项及明确不做的事情。
```

## result.md 最小模板

仅在实施结束时使用；失败、中止或阻塞也应如实记录，不创建虚假的成功结果。

```markdown
# <任务名> — 实施结果

## 完成状态
已完成 / 未完成（失败、阻塞或中止），附原因。

## 对应计划
[plan.md](plan.md)

## 实际变更与实施记录
实际变更文件及操作；如有委派，注明分工。

## 验证结果
运行过的命令与真实输出；未运行的检查及原因。

## 计划偏差
无，或说明偏差及必要的重新审批记录。

## 遗留事项
剩余工作、风险和限制。
```
