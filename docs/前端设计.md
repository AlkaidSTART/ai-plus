# InsightX 前端设计（P0，v1）

> 本文是新前端（`frontend/`）的唯一设计依据。所有「后端能做什么」的断言都标注了 `backend/...:行号` 依据；
> 未在代码中找到依据的能力一律不写、不画、不假装可用。
>
> 适用前置：`frontend/` 已被清空重建。本文不引用、不继承旧前端的任何代码、组件名、目录结构或视觉方案。

---

## 1. 设计原则与边界

1. **诚实渲染优先**：后端未实现的能力（报告、证据、聚合指标、财务/回测/视觉）一律不画成可用；有接口就调接口，没有接口就显示「后端未提供」。
2. **快照是最终状态来源**：SSE 只用于「尽快知道有变化」，任何事件到达后的权威状态都以 `GET /insight/task/{task_id}` 快照为准（后端快照在同一事务内读取，`backend/app/services/tasks.py:428-516`）。
3. **最小闭环**：`frontend/` 是单页应用，只做 3 条路由、6 个接口、1 条 SSE 通道；不引入 UI 组件库、图表库、i18n 库、状态管理库。
4. **不猜契约**：字段名、枚举值、事件名全部来自后端代码；前端类型定义是后端 schema 的镜像（`backend/app/api/schemas.py`），不做额外「设想字段」。
5. **中文单语文案**：界面文案为简体中文；后端返回的枚举（`QUEUED`/`RUNNING`/…）在前端做展示用映射，未知值原样显示。

## 2. 技术选型

| 项 | 选择 | 依据 |
| --- | --- | --- |
| 框架 | Vue 3（`<script setup lang="ts">`） | 项目既定技术栈（`AGENTS.md:10`）；本仓库既有前端为 Vue 3，重建沿用同一栈 |
| 构建 | Vite | 同上；`server.proxy` 可直接代理 `/api` 与 SSE |
| 语言 | TypeScript（`vue-tsc` 类型检查进 build） | `AGENTS.md:13` 声明 `bun run build` 含类型检查 |
| 包管理 | bun | `AGENTS.md:10,13` |
| 路由 | `vue-router` | 3 条路由需要深链与刷新保持 |
| 状态 | 组合式函数（`composables/`），不用 Pinia | 页面状态局部于单页，无跨页共享需求 |
| 样式 | 原生 CSS + CSS 变量设计令牌 | 无 UI 库依赖；视觉需要精确控制 |
| 实时 | 原生 `EventSource` | 后端为 `text/event-stream`（`backend/app/api/routes/events.py:53-57`） |

不引入：Pinia、TailwindCSS、ECharts、任何 UI 组件库、任何 i18n 库、任何 HTTP 客户端库（`fetch` 足够）。

## 3. 信息架构与路由

| 路由 | 视图 | 作用 |
| --- | --- | --- |
| `/` | `TaskListView` | 任务列表：游标分页加载、状态与分项计数、进入详情、入口跳新建 |
| `/tasks/new` | `TaskCreateView` | 新建任务：ASIN 输入与校验、幂等提交、成功后跳详情 |
| `/tasks/:taskId` | `TaskDetailView` | 任务详情：快照 + SSE 实时事件 + 取消 / 重试 |

## 4. 数据访问层

### 4.1 `src/api/client.ts`

- 基址：`import.meta.env.VITE_API_BASE_URL ?? '/api/v1'`；开发态由 Vite 代理到后端（见 §10）。
- `request()` 统一处理：`fetch` → 若 `!res.ok` 或 body 含 `error` 字段 → 解析错误信封 `{error:{code,message,details,retryable,request_id}}`（`backend/app/api/errors.py:10-42`）并抛 `ApiError`（携带 `status/code/message/details/retryable/requestId`）。
- 网络失败（`fetch` reject）抛 `ApiError`，`code = 'NETWORK_ERROR'`，`retryable = true`。
- 每个错误都在 UI 上展示 `request_id`（排查用；后端由 `RequestIdMiddleware` 注入，`backend/app/main.py:23`）。
- 成功响应：`204`/空 body 返回 `undefined`，否则 `res.json()`。

### 4.2 `src/api/tasks.ts`（6 个接口，全部按后端真实契约）

| 函数 | 方法 / 路径 | 请求 | 关键约束（依据） |
| --- | --- | --- | --- |
| `createTask(body, idempotencyKey)` | `POST /api/v1/insight/task` | `{project_id, asins, platform:'amazon', marketplace:'US', window?}` + `Idempotency-Key` 头 | 头必填（`routes/tasks.py:49-52`）；ASIN 1–10、去重、`^[A-Z0-9]{10}$`（`tasks.py:27,30-39`；`schemas.py:53-58`）；非 `amazon/US` 返回 422（`tasks.py:56-57`）；201/202 成功返回 `{task_id,status,phase,reused,window,items,links}`（`schemas.py:110-128`） |
| `listTasks(params)` | `GET /api/v1/insight/tasks` | `project_id`/`status`/`cursor`/`limit` | `limit` 默认 20、上限 100（`routes/tasks.py:87-115`）；返回 `{items, next_cursor}`（`schemas.py:184-196`） |
| `getTask(taskId)` | `GET /api/v1/insight/task/{taskId}` | — | 一致性快照（`routes/tasks.py:121-133`；`services/tasks.py:428-516`） |
| `cancelTask(taskId)` | `POST /api/v1/insight/task/{taskId}/cancel` | 无 body | 已终态时后端返回 200 且状态不变（`routes/tasks.py:136-154`） |
| `retryTask(taskId, itemIds, key)` | `POST /api/v1/insight/task/{taskId}/retry` | `{item_ids}` + `Idempotency-Key` | 仅终态任务的 FAILED 分项可重试，否则 409 `ITEM_NOT_RETRYABLE`（`routes/tasks.py:157-192`）；响应含新 `task_id` 与 `parent_task_id`（`schemas.py:131-132`） |

第 6 个接口是 SSE 通道，实现见 `src/api/sse.ts`（§5）。

### 4.3 `src/types/api.ts`

手写类型，逐字段对齐后端 schema：`TaskStatus`、`NodeStatus`、`Phase`、`Window`、`TaskCreatedResponse`、`RetryTaskResponse`、`CancelResponse`、`TaskListItem`、`TaskListResponse`、`TaskSnapshot`、`TaskItemSnapshot`、`NodeState`、`ItemProgress`、`WarningItem`、`ApiErrorBody`（依据 `backend/app/api/schemas.py:10-201`）。声明为 `type`（不可当运行时校验）；运行时按「字段缺失即空值」渲染，不抛异常。

## 5. SSE 客户端行为规范（`src/api/sse.ts`）

后端事实（必须逐条对应）：

- 地址 `GET /api/v1/insight/task/{task_id}/events?after=<seq>`；`Last-Event-ID` 头优先于 `after`（`routes/events.py:30-50`）。
- 首行下发 `retry: 3000`（`events.py:81`）；15s 无事件发注释心跳（`events.py:25-27,104-106`）；**单连接 120s 上限后服务端主动断开**（`events.py:25,107-108`）。
- 终态且追平 `max_seq` 后发 `event: stream.end`，data `{last_event_id,status}`（`events.py:98-103`；`services/events.py:71-74`）。
- 非法/超前游标返回 422 `INVALID_EVENT_CURSOR`（`events.py:45-52`）。
- 每个事件有 `id:` = seq（`services/events.py:20-34`），data 为 `{schema_version,task_id,seq,item_id,attempt,occurred_at,payload}`（`services/events.py:52-68`）。

客户端规则：

1. **建立连接**：`new EventSource('/api/v1/insight/task/{id}/events?after=' + lastSeq)`，`withCredentials = false`（后端允许携带凭证，但 P0 无 Cookie 身份）。
2. **游标**：`lastSeq` 初始取快照 `last_event_id`（字符串数字，`schemas.py:178`）。收到事件后若 `seq <= lastSeq` 则丢弃（去重），否则 `lastSeq = seq` 并回调 UI。
3. **事件类型**：显式注册 `task.updated`、`node.updated`、`item.updated`、`task.completed`、`task.failed`、`task.canceled`、`stream.end`（发出位置：初始事件 `backend/app/services/tasks.py:292-308`；其余 `backend/app/worker/graph.py:180,371,421,472,511-522`）。未注册的事件名不影响连接。
4. **终态**：收到 `task.completed|failed|canceled` 或 `stream.end` → 记录终态 → **立即 `close()`**（否则浏览器会按规范自动重连）→ 回调整体 `refreshSnapshot()`。
5. **120s 断流**：连接自然关闭时浏览器会触发 `error` 且 `readyState === CLOSED`；此时按退避重连（1s→2s→4s→…上限 15s），重连前先 `refreshSnapshot()` 取新游标。重连成功后退避重置。
6. **422 游标失效**：EventSource 对非 `text/event-stream` 响应不会自动重连，同样表现为 `error + CLOSED`。此时 `refreshSnapshot()`，用快照的 `last_event_id` 重新连；连续 3 次仍失败则停止并显示错误态 + 手动「重试连接」按钮。
7. **401/404**：停止重连，显示 `UNAUTHORIZED`/`NOT_FOUND` 错误态（后端 dev 不 401，prod 直接 401：`backend/app/api/deps.py:10-14`）。
8. **卸载**：视图 `onUnmounted` / 路由离开时 `close()`，并清理计时器。
9. **不伪造事件**：客户端不合成任何后端不存在的事件（包括 `stream.reset`，该事件后端未实现）。

## 6. 状态与视图模型

- **task 状态**（5 态，`schemas.py:10-15`）：`QUEUED` 排队中 / `RUNNING` 执行中 / `COMPLETED` 已完成 / `FAILED` 已失败 / `CANCELED` 已取消。
- **node 状态**（6 态，`schemas.py:18-24`）：`PENDING` 待开始 / `RUNNING` 执行中 / `COMPLETED` 已完成 / `FAILED` 失败 / `CANCELED` 已取消 / `SKIPPED` 已跳过（`SKIPPED` 需展示 `skip_reason`）。
- **item 状态**：与 task 同 5 态（`schemas.py:61-68`）。
- **节点列表渲染规则**（重要，避免造假）：
  - `nodes[]` 只包含**已产生执行记录**的节点（`services/tasks.py:399-425,473-475`），顺序即后端 `NODE_ORDER`（`backend/app/worker/nodes.py:5-13`）。
  - 渲染 = 快照里已有的节点 + 一行汇总「另有 N 个节点尚未开始」，其中 `N = progress.total_nodes - nodes.length`（`total_nodes` 恒为 7，`services/tasks.py:29,496`）。**不逐个命名未开始节点**，因为接口没有返回它们的名字。
  - 节点中文名映射（`ingestion` 采集 / `normalization` 规范化 / `embedding` 向量化 / `clustering` 痛点聚类 / `proposal` 双栏建议 / `evidence_validation` 证据校验 / `publish` 发布）；未知 key 原样显示。
- **进度**：`progress.completed_nodes / progress.total_nodes` 恒可用；`processed_reviews` 当前恒为 0、`total_reviews` 恒为 `null`（`services/tasks.py:497-498`）→ **不显示评论百分比**，只显示「节点 x/7」，并在数据区悬停说明「评论进度后端未提供」。
- **item_counts**：`{total,queued,running,completed,failed,canceled}`（`services/tasks.py:226-239`），列表与详情共用同一渲染（只显示非零项 + 总数）。
- **warnings**：`[{code,message,item_id}]`（`schemas.py:164-167`）。当前生产代码**不产生** `warning` 事件（写入口只存在于 `backend/tests/test_events.py:58`）→ 列表恒为空，UI 渲染「暂无告警」空态而不是隐藏该区域，便于后续后端补齐后自然显示。
- **error（分项级）**：`item.error` 为 `{code,message,retryable}`（由后端写入 `graph.py:415`），有值即展示 message 与可重试标记。
- **四类视图状态**：加载中（骨架/文字）、空数据（引导操作）、错误（错误信封 + `request_id` + 重试按钮）、部分失败（整体成功但含失败分项时，用计数与行级状态表达）。

## 7. 操作与幂等

| 操作 | 前端规则 |
| --- | --- |
| 新建任务 | 提交前本地校验 ASIN（大写、10 位 `A-Z0-9`、1–10 个、去重）；`Idempotency-Key = crypto.randomUUID()`，**同一次提交重试沿用同一 key**（改内容则换新 key）；提交中禁用按钮；成功（202）后 `router.push` 到 `/tasks/{task_id}`；`reused: true` 时提示「已复用相同请求的任务」 |
| 取消任务 | 仅非终态（`QUEUED`/`RUNNING`）可用；二次确认；成功后提示「已请求取消，等待 worker 落实」并 `refreshSnapshot()`（后端只记录取消请求：`services/tasks.py:578`） |
| 重试分项 | 仅当任务处于终态且存在 `status === 'FAILED'` 的 item 时可用；提交选中的 item_ids + 新 `Idempotency-Key`；202 后跳转到返回的**新任务**详情页；409 `ITEM_NOT_RETRYABLE` / `IDEMPOTENCY_CONFLICT` 按错误信封提示 |
| 404 / 409 / 422 / 501 | 一律展示后端 `message`，不翻译、不改写；`request_id` 以等宽小字附在提示下方 |

幂等冲突（`IDEMPOTENCY_CONFLICT`，`errors.py:13`）含义是「同一 key 提交了不同内容」（`routes/tasks.py:76-82`）——UI 文案需明确提示，而不是笼统「提交失败」。

## 9. 视觉系统与文案

设计方向：**「档案台」——编辑部式的数据工作台**。不是通用后台模板：用纸质底色 + 墨色正文 + 单一朱砂强调色 + 规则细线，营造「可信档案」的观感；数据用等宽字体，标题用衬线字体。

- 令牌（`src/styles/tokens.css`，全部以 CSS 变量暴露）：
  - 纸色 `--paper: #F4F1EA`、卡片 `--surface: #FBF9F4`、墨色 `--ink: #191B1E`、次级 `--ink-muted: #5F6168`、细线 `--rule: #DCD5C6`
  - 强调朱砂 `--accent: #C2402A`；成功苔绿 `--ok: #47684F`；警告赭 `--warn: #A76B24`；错误同朱砂；信息灰蓝 `--info: #45566B`
  - 字体：标题 `Songti SC / Noto Serif SC / Georgia, serif`；正文 `PingFang SC / Hiragino Sans GB / system-ui`；数字与 ID `SFMono-Regular / JetBrains Mono / Menlo, monospace`
  - 直角优先（`--radius: 2px`），细线分隔代替阴影卡片堆叠
- 动效：CSS 实现，`prefers-reduced-motion: reduce` 时全部关闭；运行中状态用呼吸点；列表首屏一次性 60ms 交错淡入；进度条宽度过渡 200ms。
- 背景：极淡的斜向细线网格（`repeating-linear-gradient`），不使用图片资源。
- 文案：动词+宾语（「新建任务」「加载更多」「取消任务」），错误提示保留后端原文，空态给出下一步操作路径。
- 可访问性：状态不只靠颜色（同时有文字标签）；表格用语义 `<table>`；按钮 `type="button"`；交互控件有可见焦点环。

## 12. 分阶段与验收

- **F0** 脚手架 + 路由 + API/SSE 客户端 + 设计令牌
- **F1** 任务列表（游标分页）+ 新建任务（校验 + 幂等 + 跳转）
- **F2** 任务详情（快照 + SSE 实时事件 + 节点/分项进度）
- **F3** 取消 / 重试 / 告警 / 错误与 `request_id` 呈现
- **F4**（本轮不做，留待联调）真实后端端到端跑通与视觉打磨

验收（可执行）：
